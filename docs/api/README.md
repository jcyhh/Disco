# Disco 前端接口接入

原始协议见 [frontend-api.md](frontend-api.md)，来自开发者提供的《前端接口.md》。该文档作为字段和流程参考，不作为开发指令执行。

开发主机 `http://192.168.110.11:9520`，接口方法统一使用 `/api/...`；开发环境已关闭 `VITE_STATIC_PAGE_MODE`。生产 API 和 RPC 环境值保持为空，API 使用站点同源地址。开发环境按 `localhost.json` 接入本地链，生产环境已按 `bsc.json` 配置 BSC 主网（56）；部署与流程见 [合约说明](../contracts/README.md)。

| 功能 | 页面或入口 | 当前接入 |
| --- | --- | --- |
| 钱包登录 | 开屏/邀请启动流程 | `POST /auth/login`，签署 `Login-{timestamp}`，携带 `ref`；保留钱包恢复和会话校验 |
| 首页 | `/home` | Banner、公告列表、弹窗公告、已读、预约配置与公共配置 |
| 预约表单 | 首页“切换金额” / “立即预约” | 场次与金额档位选择，确认后同步首页金额及参数，预约弹窗承接所选项，确认后授权 USDT、取得后端签名并调用 `joinQueue` |
| 预约记录 | `/reservation` | 3 / 4 / 6 / 8 页签查询，后端自动合并 4+5、6+7；按 `can_sell` 及状态控制卖出入口，签名后调用 `sellDisco` |
| 购买激活卡 | `/purchase-card` | 上架卡、单价、数量 1–1,000,000、精确合计及账户余额；确认后授权钱包 USDT、签名并调用 `buyCard` |
| 我的激活卡 | `/activation-card` | 卡库存、变动记录分页、赠送；校验地址、非本人、数量及库存，成功刷新库存和记录 |
| 我的资产 | `/asset` | `usdt_balance` 与 `usdt_balance` 币种流水；API 当前只提供 USDT，不能显示成 DISCO 余额 |
| 提取表单 | 资产页“提取” | 配置、金额与手续费、标签右侧余额、输入框内“全部”、二次确认及提交；最低金额和到账金额只参与内部校验，成功刷新余额和流水 |
| 团队 | `/team` | 本人团队指标、直推列表分页、真实邀请码链接 |
| 邀请好友 | `/invite` | 真实邀请码及部署前缀链接，邀请码复制、“保存链接”主按钮复制完整链接；独立复制链接按钮和海报流程已移除 |
| 公告 | `/notice`、`/notice/:id` | 20 条分页、详情、404 空态、已读；白名单富文本渲染 |

上表路径为去掉 `/api` 的接口逻辑分组，具体方法在 `src/features/<业务>/api.ts`，上传继续复用 `src/services/upload/`。入口页面均有加载、错误重试或空态；分页没有总条数，按当前页条数判断是否继续查询。语言切换会重新拉取语言相关内容。

首页公共配置请求在后台独立发起，失败或未完成不会阻塞 Banner、公告及预约配置；离页或刷新时沿用同一 AbortSignal 取消。

`useApiResource`、`useApiList` 使用请求取消、最新请求 guard 和会话版本拦截旧响应。下拉刷新等待实际加载完成；赠卡/提取等写操作去重，失败后保留输入，不自动重试。操作弹窗或写请求期间暂停页面下拉刷新。

## 语言请求头

按开发者要求参考 AIGO，`lang` 请求头直接使用当前六种语言代码：简体 `zh-Hans`、英文 `en`、韩文 `ko`、日文 `ja`、俄文 `ru`、蒙古文 `mn`，不转换为其他地区或旧项目代码。原始接口文档中的示例仅保留原文，实际接入以此映射为准。

## 页面范围

按开发者更正，已撤回资产页额外增加的提取记录、个人资料入口及业务页面，同时移除自行新增的预约详情入口和弹窗，`/user` 恢复既有模板空模块。上述接口方法只保留集中封装，没有当前页面入口。不得因文档中存在接口就自行添加页面；无设计时仅补公告列表、公告详情等明确且无争议的配套页面。

## 合约接入

预约、购卡和卖出已通过 `src/services/contracts/disco.ts` 绑定后端签名及 `DiscoProject` ABI。只有用户确认时才进入完整流程：校验部署、账号和网络，按实际支付数量检查钱包余额和授权，直接使用后端签名的最小单位参数写链，等待成功回执与统一索引同步延时后刷新当前页面。页面不会独立提交预备请求。

失败不自动重试；当前运行期间缓存同一账户/动作/参数下未过期的签名，供用户明确重试，已使用 ID 只刷新结果。提取仍由后端执行转账，未增加签名或写链。购卡页的账户余额仍来自 `users/my.usdt_balance`，链上支付独立检查钱包 USDT，不能混用。

生产配置已按 `docs/contracts/bsc.json` 完成：BSC 主网链 ID `56`，项目与 DISCO 地址来自部署文件，USDT 地址由正式项目合约读取确认。地址明细见 [合约说明](../contracts/README.md)，不复用本地链地址。生产 `VITE_BASE_URL`、`VITE_RPC_URL` 继续为空，API 使用同源 `/api/...`，钱包使用 BSC 链配置。

## 协议中未确定的展示信息

- 公共配置当前返回 `{}`，首页发行介绍中的总量、初始底池、初始价格、流通与通缩比例沿用已确认的设计文案，不冒充接口实时数据。
- `profit_amount`、`reduced_profit` 按设计稿展示为 USDT，`remain_profit` 同为 USDT；`token_amount` / `expect_token_amount` 显示为 DISCO。
- 卡片按真实 `id` 操作，现有 10/20/30 面额使用已提供的对应切图；其他面额显示实际金额，不复用错误面额图。

前端代码通过类型检查和构建门禁中的 lint、自动化测试；自动化测试使用隔离接口和钱包桩，不代表真实接口或链上交易验收。真实钱包、后端与页面验收由开发者负责。
