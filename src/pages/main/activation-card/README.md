# 当前接口接入

当前卡列表、名称、售价、卡 ID 和持有数量全部来自 `/api/activation_cards`。`src/features/activation-card/config.ts` 只保留购卡页和本页的本地封面资源，按接口列表顺序使用，不配置卡名、价格或固定业务列表。接口未返回的卡不额外生成。转赠按真实卡 ID 提交 `/api/activation_cards/gift`，校验地址、非本人、正整数、库存上限及最多一百万张；成功后刷新库存和记录。记录直接展示已加载列表，每页 20 条，向下滚动由 `InfiniteScroll` 自动加载下一页；失败保留重试入口。

调试结束，已恢复转赠入口零库存禁用、弹窗零库存拦截及提交前库存上限校验。转赠复用登录的钱包签名封装 `signDappMessage('Transfer')`，签署 `Transfer-{Unix 秒}` 后将 `signature`、`timestamp` 一并传给赠送接口。签名期间防止重复提交，拒签保留表单供重试；离页或登录会话变化后不继续提交旧签名。记录中的 `from_address` 按接口文档作为转赠对方地址展示，为空时不显示地址行。

页面及真实钱包验收由开发者负责。完整接口映射见项目 `docs/api/README.md`。下方为保留的历史静态设计/资源记录，其中 mock 行为不再用于当前页面。

# 我的激活卡静态页面

页面参考 [Figma 节点 31024:3260](https://www.figma.com/design/NVwAAv12WZx1LiCTqPMNWD?node-id=31024-3260)，展示卡片、拥有数量及获得记录，当前处于第 1 步静态页面开发，页面视觉和交互验收由用户负责。

## 本地数据与交互

`src/mock/activation-card.ts` 提供三种面值：10、20、30，对应拥有数量为 10、2、0。当前记录展示以开头的真实接口与滚动分页说明为准。

历史静态阶段的“转赠”使用本地表单，校验接收钱包地址、正整数数量及现有库存上限。当前行为以上方接口接入说明为准。校验通过后的确认仅关闭弹窗，不进行实际交易、不改变库存，也不触发 API/RPC。

设计中的“转增”统一使用“转赠”。简体中文、英文和繁体中文词条均已补齐。卡片与按钮复用现有封装，保留已固定的 Header、左侧侧栏、六项菜单、品牌、单图标语言开关及主题，不修改公共默认值。

## 页面资源

页面资源均已从 Figma 下载到 `src/assets/activation-card/`：`hero-banner.webp`、`card-10.webp`、`card-20.webp`、`card-30.webp`，以及原样保留的 `hero-overlay.svg`、`card-decoration.svg`、`gift.svg`、`more-arrow.svg`。

四张大图等比缩放、保持全幅并转换为 WebP，总体积从 10,676,687 bytes 降为 616,436 bytes，减少约 94.23%。SVG 保留下载文件原始字节；章节装饰复用公共资源。

页面只消费本地 mock，不注册虚假刷新或进入接口、合约联调。
